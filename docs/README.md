# QuakeCurrent 문서

이 디렉터리는 QuakeCurrent의 현재 상태, 설계 판단과 검증 방법을 역할별로
분리합니다. `SSOT.md`는 모든 구현 세부를 복사한 문서가 아니라, 제품 수준의
현재 사실과 각 기술 영역의 권위 소스를 연결하는 기준 문서입니다.

## 문서 지도

| 문서 | 책임 | 언제 갱신하는가 |
| --- | --- | --- |
| [SSOT](./SSOT.md) | 현재 제품 범위, 비범위, 상태와 권위 소스 | 범위·상태·운영 정책이 바뀔 때 |
| [아키텍처](./ARCHITECTURE.md) | 구성요소, 의존 방향, 데이터·실시간 흐름 | 시스템 경계나 데이터 흐름이 바뀔 때 |
| [워크플로우](./WORKFLOW.md) | Prototype → Plan → Autopilot → Review 실행 규칙 | 개발·검토 절차가 바뀔 때 |
| [결정 기록](./DECISIONS.md) | 채택한 판단, 이유와 재검토 조건 | 중요한 기술·제품 결정을 내리거나 뒤집을 때 |
| [검증 가이드](./VERIFICATION.md) | 로컬·CI 검증 명령과 증거 해석 | 테스트·CI·품질 기준이 바뀔 때 |

세부 실행 방법은 [루트 README](../README.md), 백엔드는
[API README](../apps/api/README.md), 생성 클라이언트는
[API 클라이언트 README](../packages/api-client/README.md)를 함께 봅니다.
과거 사이클의 결과와 당시 증거는 웹 앱의 `/build-log`에 기록합니다.

## 권장 읽기 순서

1. 처음 보는 사람: 루트 README → SSOT → 아키텍처
2. 기능을 변경하는 사람: SSOT → 결정 기록 → 워크플로우 → 검증 가이드
3. 계약을 변경하는 사람: SSOT의 권위 소스 표 → API/API 클라이언트 README

## 문서 정합성 규칙

- 코드·스키마·마이그레이션·잠금 파일처럼 실행 가능한 계약을 설명 문서보다 우선합니다.
- 설명 문서와 실행 가능한 계약이 다르면 문서 불일치 결함으로 보고 같은 변경에서
  함께 수정합니다.
- README에는 빠른 진입점만 두고, 현재 범위는 SSOT, 이유는 결정 기록, 과거 결과는
  빌드 로그에 둡니다.
- 검증하지 않은 배포·트래픽·성능 결과를 현재 사실처럼 기록하지 않습니다.
- 상대 링크는 저장소 루트의 `npm run check:docs`와 CI에서 검사합니다.
